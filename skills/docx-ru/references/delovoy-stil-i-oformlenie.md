# Деловой стиль и оформление — канон

Собрано из практики правки деловых пакетов документов для промышленного партнёра (комплект письма, обоснование стоимости техпроекта, приложения к договору). Компания-пример ниже условно называется «Партнёр» — подставляйте своего контрагента.

## Типографика (Word)

| Элемент | Значение |
|---------|----------|
| Шрифт | Times New Roman |
| Основной текст | 12 pt |
| Заголовок документа | 14–16 pt, жирный |
| Заголовки разделов | 12–14 pt, жирный |
| Цвет текста | Чёрный (#000000), без серых/синих стилей pandoc |
| Межстрочный интервал | 1,15–1,5 (если правишь через python-docx — `WD_LINE_SPACING.MULTIPLE`, ~1.15) |
| Поля | **2,54 cm** со всех сторон (эталон-стандарт); допустимо 2–2,5 cm |

**После pandoc** шрифты часто Consolas/Aptos — это дефект, не стандарт. Всегда прогонять `normalize_docx.py`.

## Язык и терминология

### Английское → русское (для внешних docx)

| Нельзя | Нужно |
|--------|-------|
| take-or-pay / «бери или плати» | **условие принятия либо оплаты** |
| Make-up right / «право добора» | **право на последующую выборку** |
| fallback | **запасной переговорный вариант** (только во внутренних md; **удалять** из docx для контрагента) |
| deliver-or-pay | **условие принятия либо оплаты** |

### Разговорное → деловое

| Нельзя наружу | Нужно |
|---------------|-------|
| легализация (в товарном обороте) | **оформление в товарный режим** |
| под ключ | **организация и финансирование оформления в товарный режим** |
| жёсткий / компромиссный вариант | **п. X.Y** в договорной редакции (без меток переговоров) |

### Единицы и символы

- **₽/м³**, **м³**, **₽/т**, **т/км** — кириллическая «м»
- Запрещены homoglyphs: `₽/m³`, `m³`, латинская «a» в кириллических названиях и т.п.
- Разделитель дробной части — запятая: **0,35** (в таблицах допустима точка, но единообразие в документе)
- Тире — среднее «—», не `--` из markdown
- Дефисы — ASCII `-`, не U+2011

## Структура по типам

### Справка / обоснование / расчёт (партнёр, финслужба)

1. Титул (title, subtitle, date, audience) в YAML
2. **Резюме для партнёра** — ½–1 стр.: задача, сценарии, ключевые цифры, вывод
3. Нумерованные разделы с таблицами
4. Сценарии **А/Б** явно, с допущениями
5. Экономика — **с базисом цены** (например, отгрузка со склада / доставка до станции / пункт поставки)
6. Риски, нормативка, приложения
7. Оглавление (pandoc `--toc`)

### Письмо контрагенту (гендиректор, юрслужба)

- Уважительный тон, **без ультиматумов** и «10 рабочих дней» в мягком треке
- Список приложений: **1. 2. 3.** с **количеством листов** (считать из pdf)
- Исх. № и дата — пустые в черновике, если ещё не присвоены
- Не включать документы из «жёсткого трека», если статус проекта — мягкое письмо

### Приложение к письму

- Первая строка: **«Приложение N к письму …»**
- Только тело: **без** шапки другого письма, **без** блока «Исх. №», **без** чужого списка приложений
- Если источник — письмо юрслужбе: брать только релевантные содержательные разделы, без подписи и сроков

### Договор / допсоглашение

- Нумерация §1, §2 или 1., 1.1.
- Юридический язык, без служебных пометок в конце
- Проект для юристов — можно пометить в **имени файла** или сопроводительном письме, не внутри текста договора

## Запрещённые паттерны (автоскан)

```
Служебная пометка | Черновик | не для отправки
10 рабочих дней          (если мягкий трек)
Table of Contents
take-or-pay | make-up | fallback
```

Проверяйте также ссылки на статьи закона — ошибочная нумерация в скане не ловится, нужен ручной юридический контроль.

## Pandoc — частые ошибки

| Ошибка | Решение |
|--------|---------|
| Table of Contents | `--metadata=toc-title:"Оглавление"` |
| Consolas вместо TNR | `normalize_docx.py` |
| `--toc-title=` не работает | `--metadata=toc-title:"Оглавление"` |
| Таблицы широкие | упростить столбцы в md; проверить в Word |

## Эталонные образцы

Держите 2-3 «золотых» примера уже отправленных документов в своей документной базе (письмо, обоснование с оглавлением, аналитический комплект без оглавления) и при сомнении открывайте эталон и **копируйте оформление**, не изобретайте заново.

## Аналитика (DD, сравнение, профиль партнёра)

- **Не** использовать `--toc` — оглавление не нужно
- Pipeline: pandoc → `normalize_docx.py` → `format_analytical_docx.py` → `validate_analytical_docx.sh`
- Термины энергетики/ЦОД (если ваша ниша — этот домен): см. `docx-analytical-ru/references/terminologiya-analitika.md`
- Два тона: внутренний (риски) / внешний (без DD-блока)
